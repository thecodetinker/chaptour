# Continuous deployment, no manual approval gate

Merging to `main` deploys to a staging slot, runs an automated smoke/health check, then swaps to production automatically — no human approval step in between. This might look unusual for a production Azure app, where manual approval gates before prod are common practice. We're skipping it because `/implement` already runs `/code-review` before anything is committed to `main`, so code quality is checked before it reaches this pipeline at all; for a solo-curated v1, a second manual gate would just be re-reviewing the same change. The slot swap is a one-command rollback if something's wrong post-swap, which is the actual safety net here. Revisit once there are other people's changes landing on `main` without the same review discipline, or once a bad deploy would be genuinely costly.
