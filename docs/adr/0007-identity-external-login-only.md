# ASP.NET Core Identity, external logins only — no local passwords

Authors are a small, invite-only set for v1 (ADR-0002); Followers never authenticate at all. Entra External ID/B2C was the first instinct, but it's a full CIAM platform sized for self-service consumer signup at scale — overhead this small, curated Author surface doesn't need yet. Storing local passwords via plain ASP.NET Core Identity was rejected too: even hashed, the app would own the credential store and the liability that comes with it, which we specifically want to avoid. We're using ASP.NET Core Identity's local user table (so an Author record exists in our DB) configured for **external logins only** — Authors sign in with an existing Google or Microsoft account, Identity just maps that external identity to their local Author record. No password is ever stored, and no new Azure resource is needed. Revisit this when self-serve Author signup (deferred in ADR-0002) actually gets built — that's when Entra External ID's self-service infrastructure starts earning its cost.
