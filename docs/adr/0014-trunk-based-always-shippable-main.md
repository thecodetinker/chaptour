# Trunk-based: every commit on main must be shippable

Continuous deployment with no manual gate (ADR-0010) is only safe if `main` is always in a genuinely deployable state — that's a discipline, not a pipeline setting, so it's worth recording as its own decision rather than leaving it implied. This means tickets are sliced into small, independently-shippable increments (as `/to-tickets` already does via tracer-bullet tickets), incomplete work stays off `main` rather than living on long-running feature branches, and anything that must land before it's fully user-facing goes behind a feature flag rather than an unmerged branch. The alternative — longer-lived branches merged in bigger batches — was rejected because it's exactly what turns "checks pass, therefore ship" from a real guarantee into a hopeful one.
