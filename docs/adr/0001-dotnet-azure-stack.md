# Build on .NET/Azure rather than an AI-optimized stack

Chaptour is being built as a real product and as a deliberate exercise in an AI-first (agent-driven) workflow. The obvious alternative was a TypeScript/Node-based stack, which has denser training data and more agent tooling built around it, likely producing faster/cleaner first-pass agent output. We chose .NET on Azure instead, because the author (a C# developer and Azure architect) is new to the AI-first workflow, not to the language — deep stack fluency is what lets a human reviewer catch subtle mistakes in agent-generated code. Optimizing the process for AI-first was judged more valuable here than optimizing the language for the agent. (Which .NET web framework specifically is a separate decision — see ADR-0004.)
